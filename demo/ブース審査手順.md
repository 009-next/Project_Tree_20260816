# ブース審査 進行表（3案件・プロンプト3種）

ブースで実際にアプリを動かすための一式です。**フォールバック（プリセット）による出力は使いません。**
2D/3Dモデルは3案件とも「記録から作成（LLM）」で起こします。

---

## 用意してあるもの

| 案件 | 資料 | 見どころ |
|---|---|---|
| **河川護岸整備工事** | 6件（議事録2・メール4） | 出水期の制約、濁水対策、農地への影響 |
| **東部橋梁補修工事** | 5件（議事録3・メール2） | 工期変更が3回連続、特注品の納期遅延 |
| **旧緑ヶ丘小学校校舎解体工事** | 9件（議事録4・メール3・計画書・報告書） | アスベスト、処分費増額、近隣説明 |

学校案件は**プリセットに当たらない工種**なので、「記録からLLMがモデルを起こす」ことを
最も分かりやすく示せます。護岸・橋梁もプリセットを使わず同じ経路で作ります。

---

## 準備（ブース開始前に済ませる）

```bash
python demo/reset_demo.py --inbox
```

0件の台帳に差し替え、`取込フォルダ` に3案件を置きます。
このあと **exe を起動するだけで資料が取り込まれた状態**になります（原価0円）。

> **重要**：解析（▶出力）は1案件あたり約6.5分かかります。ブースの持ち時間では
> 完走を待てないため、**事前に1回流して完成状態を作っておき**、
> 審査員には「0件→取込→見積り提示」までを実演するのが現実的です。
> 完成済みの台帳は `python demo/reset_demo.py --restore` で戻せます。

---

## 進行（1人あたり5〜7分を想定）

### ① 起動して「取り込み済み」を見せる（30秒）

コンソールに `取込フォルダから 3 案件・資料 20 件を取り込みました` と出ます。
**「フォルダを置いて起動しただけ。ここまで原価0円」**と説明してください。

### ② ⚙設定でAPIキーを入れる（30秒）

`sk-orca-…` を入れて「接続確認」。**キーはメモリ上だけで保存しない**ことを添えます。

### ③ ▶出力 を押し、見積りダイアログを見せる（1分）

**ここが審査項目⑥（LLMコスト）の見せ場です。**
モデル名・概算トークン・金額が承認前に出ることを指差してください。

時間が無ければ、ここで**キャンセル**し「実行済みのものをお見せします」と切り替えます。

### ④ 完成した案件で操作を見せる（2〜3分）

| 操作 | 見せどころ | 対応する審査項目 |
|---|---|---|
| 段階カードを**左クリック** | 根拠の記録→**元資料の原文**まで戻れる | ①課題の実在性 |
| 段階カードを**右クリック** | md/pdf/word/pptx/xlsx で出力 | ③完成度 |
| 3Dモデルの部位を**左クリック** | 対応する段階が光る | ④AI必然性 |
| 表示段階スライダー | 指定段階までの部材だけ表示 | ③完成度 |

### ⑤ プロンプトで推論を見せる（1〜2分）

下記のプロンプトを入力し、**根拠の件数と「捏造ID 0件」**を指差します。
**これが審査項目④（AI必然性）と⑦（信頼性）の核心**です。

## プロンプト3種（実測で検証済み）

そのままコピーして使えます。いずれも**捏造ID 0件**で、根拠つきの回答が返ることを確認済みです。

### 1. 河川護岸整備工事

```
出水期の制約で工程が遅れた原因と、濁水対策として何がどこまで決まったかを、記録を根拠に整理してください。
```

実測の回答例（172秒・$0.0343・根拠3〜4件・捏造0件）:
- 遅延の直接原因は出水期の河川内作業制約。5/15の水位上昇リスク懸念が6/1の3日間中断として現実化
- 濁水対策は仮設沈砂池の検討依頼→設計完了予定6/30→増設の合意（6/15）までが決定範囲

### 2. 東部橋梁補修工事

```
工期変更が繰り返された経緯と原因を整理し、次に手を打つべき点を提案してください。
```

実測の回答例（89秒・$0.0403・根拠3〜4件・捏造0件）:
- 主因は特注品の長納期（約8週間）と5/29の製造不良による再製作
- 延長は3回連続（約3週間→約1ヶ月→約1ヶ月）。**逐次的な小刻み延長で根本原因が解消されていない**

### 3. 旧緑ヶ丘小学校校舎解体工事

```
費用と工期が増えた要因を特定し、まだ決着していない論点を挙げてください。
```

実測の回答例（49秒・$0.044・根拠4件・捏造0件）:
- 費用増はコンクリートがら量が想定比約15%増加したことによる処分費増額
- 工期増は理科室配管保温材の除去工法変更で約2週間延伸
- 増額98万円は7/31に承認、8/5に契約変更完了

> **推論は1回あたり50〜170秒**かかります。ブースで待たせたくない場合は、
> 事前に実行して結果を画面に残しておき、プロンプト文だけ見せてください。

## モデルは必ず「記録から作成（LLM）」で

護岸・橋梁は名前がプリセット（護岸／橋梁）に当たるため、
「▶出力」の中のモデル生成工程は**プリセットの形**を使います。
プリセットは既製の形なので、**審査でLLM生成として見せてはいけません。**

3案件とも、進捗パネルの **「2-2. 記録から作成（LLM）」** を押してモデルを作ってください。
台帳の記録から寸法を推定するため、工種に応じた別々の形になります。

| 案件 | 記録から起こしたモデルの例 |
|---|---|
| 護岸 | 掘削・基礎工・護岸ブロック・天端工 |
| 橋梁 | 橋台・橋脚・主桁・床版・伸縮装置 |
| 学校 | 仮囲い・防音パネル→校舎躯体→がれき集積→更地 |

作成後、部位一覧の表示が `source=llm` になります。
プリセットで作った場合は `source=local` です。**この違いを聞かれたら正直に説明してください。**

同梱の台帳は既にこの状態にしてあります（実測で確認済み）。

| 案件 | 部位 | 形の例 | source |
|---|---|---|---|
| 河川護岸整備工事 | 7 | 護岸ブロック積み(法面)=slope、基礎工、仮設沈砂池 | **llm** |
| 東部橋梁補修工事 | 8 | 橋脚=cylinder×2、床版、伸縮装置、護岸法面=wedge | **llm** |
| 旧緑ヶ丘小学校校舎解体工事 | 8 | 校舎躯体、体育館側棟、廃材仮置き山=cone、更地 | **llm** |

プリセット由来の2D/3D資産は台帳から取り除いてあるので、
**画面に出るモデルは必ずLLMが起こしたもの**です（段階カードの画像は別物なので残っています）。

## 聞かれたら答えること

- **「この資料は本物か」** → 実案件を模した合成データ。守秘義務で実資料は持ち出せない
- **「モデルはプリセットでは」** → 学校案件はプリセット非該当。記録から起こしている
- **「認証は」** → APIに認証は未実装。だから公開版は閲覧専用にしている

想定問答の全文は別途の想定問答集を参照してください。
