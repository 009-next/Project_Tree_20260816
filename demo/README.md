# 当日デモ手順（0件の状態からフォルダ取込で再現する）

審査員の前で「何も無い状態」から始め、フォルダを取り込んで案件が組み上がる様子を見せるための一式です。

```
demo/
├── 河川護岸整備工事/     取り込む資料 6件（議事録2・メール4）
├── 東部橋梁補修工事/     取り込む資料 5件（議事録3・メール2）
├── 空の台帳/ledger.db    案件0件の台帳（これに差し替えると0から始まる）
├── reset_demo.py        台帳の差し替え・復元スクリプト
├── 実測ログ.md          所要時間と原価の実測値
└── README.md            この手順書
```

---

## 準備（デモ前に1回）

同梱の `ledger.db` は4案件が入った状態なので、**0件の台帳に差し替えます。**

```bash
python demo/reset_demo.py
```

現在の台帳は `ledger_backup_日時.db` として自動で退避されます。
元に戻すときは、そのファイルを `ledger.db` に戻すだけです。

```bash
python demo/reset_demo.py --restore
```

## 当日の流れ

### 1. 起動（案件0件を見せる）

`Project_Tree.exe` を起動します。左の一覧が空であることを見せてください。
起動時のコンソールにも `案件数: 0 件` と出ます。

### 2. APIキーを入れる

画面右上の **「⚙ 設定」** を開き、キーを入力します。

- Claude を直接使う場合は `sk-ant-…` を上の欄へ
- Orca Router を使う場合は `sk-orca-…` を下の欄へ

**「接続確認」** を押して `ok` が返れば準備完了です。再起動は不要です。

> キーはメモリ上にしか保持しません。アプリを終了すると消えるので、
> デモのたびに入れ直してください。

### 3. フォルダを取り込む（原価0円・一瞬で終わる）

> **事前に済ませておく方法もあります。**
> exe と同じ場所に **`取込フォルダ`** を作り、その中へ案件フォルダを置いておくと、
> **起動しただけで取り込まれた状態**になります（画面操作は不要）。
>
> ```
> Project_Tree.exe
> 取込フォルダ/
>   ├── 河川護岸整備工事/
>   └── 東部橋梁補修工事/
> ```
>
> 起動時のコンソールに「取込フォルダから 2 案件・資料 11 件を取り込みました」と出ます。
> LLMは呼ばないので**原価0円**です。取り込んだフォルダには `.取込済み` という
> 目印が残り、次回以降は読み飛ばされます（消すとまた取り込みます）。
> `取込フォルダ` が無ければ従来どおりの起動になります。
>
> 画面で取り込む様子を見せたい場合は、この方法を使わず下記の手順で操作してください。

「📁 案件」パネル →「**プロジェクトフォルダを選ぶ**」で
`demo/河川護岸整備工事` を選びます。**フォルダ名がそのまま案件名**になります。

同じ手順で `demo/東部橋梁補修工事` も取り込みます。

この時点ではまだLLMを呼んでいないため**原価は0円**、所要**1秒未満**です。
資料12件が台帳に入りますが、記録がまだ無いので一覧には出ません。

### 4. 「▶ 出力」で解析する（ここでLLMを使う）

左下の **「▶ 出力」** を押します。実行前に**概算費用のダイアログ**が出るので、
審査員に金額を見せてから承認してください。

9工程（取込 → 時系列 → 案件割当 → 段階分類 → 2D/3Dモデル → 進捗 →
部位対応 → イメージ図 → 推論）が順に走ります。

### 5. 完成した案件を見せる

一覧に2案件が並びます。あとは通常のデモと同じです。

| 操作 | 起きること |
|---|---|
| 段階カードを左クリック | 根拠の記録と元資料の原文へ |
| 段階カードを右クリック | md / pdf / word / pptx / xlsx で出力 |
| 3Dモデルの部位を左クリック | 対応する段階カードが光る |
| 表示段階スライダー | 指定段階までの部材だけ表示 |

## 所要時間と原価の目安（実測値）

| 工程 | 時間 | 原価 |
|---|---|---|
| フォルダ取込（手順3） | 1秒未満 | **0円** |
| 「▶出力」1案件あたり | 下記の実測を参照 | 下記を参照 |

実測値は [実測ログ.md](実測ログ.md) に記載しています。**1案件あたり約6.5分・$0.25**（並列化により19分から短縮）。

> **時間が読めない場合の逃げ道**（並列化後も1案件6分半かかります）
> 「▶出力」はイメージ図の生成に時間がかかります。持ち時間が短いときは、
> **手順3までを見せて**「ここから先は数分かかるので、完成済みのものをお見せします」と言い、
> `python demo/reset_demo.py --restore` で4案件入りの台帳に戻す方が安全です。
> 事前に一度実行しておき、当日は取込までを実演する運用を推奨します。

## 注意

- 同じフォルダを2回取り込んでも、内容ハッシュが同じなら**重複として弾かれます**（再課金されません）
- `.eml`（メール）も取り込めます。件名・差出人を本文の先頭に残したうえで解析します
- 取り込んだ資料は `ledger.db` に入ります。元のフォルダは移動・削除されません

## この手順を用意する過程で直した不具合

当日そのまま踏むことになるため、記録として残します。

**1. メール（.eml）が取り込めなかった**
画面からの取り込みは `.txt .md .pdf .docx .pptx` と画像しか受け付けておらず、
12件のうち**メール6件が拒否**されていました。一括取込の `ingest.py` には
`.eml` の解析処理が元からあったのに、画面側だけが弾いていた形です。
`intake.py` に `.eml` を追加し、`ingest.parse_eml()` を再利用するようにしました。

**2. フォルダ取込が独自の拡張子リストを持っていた**
`foldersync.py` が `intake.py` と同じ集合を書き写しており、上記を直しても
フォルダ取込だけが `.eml` を拒否し続けました。二重管理をやめ、
`intake.ACCEPTED_EXT` を参照する形に変えています。

**3. Orca Router 経由で抽出が全件失敗していた**
`extractor.py` は `llm.MODEL_EXTRACT`（"claude-haiku-4-5"）という
Anthropic の名前を直接使うため、Orca へは `anthropic/` 接頭辞なしで渡り、
**503 model_not_found で全件落ちて events が0件**になっていました。
`autorun.py` が既にクライアントを差し替えているのと同じ要領で、
呼び出しの間だけモデル名も接続先に合わせるようにしました（threader も同様）。

いずれも `extractor.py` `threader.py` `llm.py` 本体は変更していません。
